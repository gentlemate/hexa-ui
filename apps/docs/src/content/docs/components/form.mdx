## Import

```js
import "onent-ui/form";
```

`oui-form` also loads [`oui-form-field`](../form-field/). Import the controls you use.

        </oui-form-field>
        <oui-form-field name="password" label="Password" hint="At least 8 characters." required>
            <oui-input type="password"></oui-input>
        </oui-form-field>
        <oui-button type="submit">Create account</oui-button>

    </form>
</oui-form>`}

```js
import * as v from "valibot";

const form = document.querySelector("oui-form");

form.schema = v.object({
    email: v.pipe(v.string(), v.email("Enter a valid email address.")),
    password: v.pipe(v.string(), v.minLength(8, "Use at least 8 characters.")),
});

form.addEventListener("oui-submit", (event) => {
    console.log(event.detail.data);
});
```

## Structure

```html
<oui-form>
    <form>
        <oui-form-field>
            <oui-input></oui-input>
        </oui-form-field>
        <oui-button type="submit"></oui-button>
    </form>
</oui-form>
```

The `<form>` is required: inside the Shadow DOM of `oui-form`, it would not own the controls. The browser never submits it, so `action` and `method` have no effect.

## Examples

### Schema

`schema` takes any [Standard Schema](https://standardschema.dev/): Valibot, Zod, ArkType… No validation library is bundled. Errors go to the `oui-form-field` of the same `name`. `event.detail.data` is the output of the schema, with its transformations.

Without `schema` nor `validator`, the browser checks the controls, and `required` blocks the submission.

### Custom validation

`validator` receives the state and returns a list of errors, or a promise of one. It is combined with `schema`. Try `admin` here.

<Preview
    stack
    code={`<oui-form data-demo="validator">
    <form class="flex flex-col gap-4">
        <oui-form-field name="login" label="Login">
            <oui-input></oui-input>
        </oui-form-field>
        <oui-button type="submit">Check</oui-button>
        <p data-result class="text-muted-foreground text-sm"></p>
    </form>
</oui-form>`}
/>

```js
form.validator = async ({ login }) => {
    const taken = await isTaken(login);
    return taken ? [{ name: "login", message: "This login is already used." }] : [];
};
```

### Validation triggers

`validate-on` lists the events of a field that validate it, among `blur`, `change` and `input`. Submitting always validates.

Validation on `input` waits for the first blur of the field, then runs `validate-on-input-delay` milliseconds after the last keystroke. A field with [`eager-validation`](../form-field/#eager-validation) or with an error does not wait for the blur.

<Preview

            <oui-input type="email"></oui-input>
        </oui-form-field>
        <oui-form-field name="password" label="Password" eager-validation>

### State

`state` reads and writes the values of the named controls. Values are typed: a number for `oui-number-field` and `oui-slider`, a boolean for `oui-checkbox` and `oui-switch`. Dots in a name create nested objects.

The initial values, also restored on reset, can be set in three ways:

- `value` or `checked` on each control, without JavaScript.
- The `state` attribute, as JSON.
- The `state` property, for example with the response of an API. The last assigned state is the one restored on reset.

`dirty` tells whether the user changed a control since the last reset or assignment of `state`.

### Asynchronous submission

The promise given to `event.detail.waitUntil()` keeps the form `submitting` until it settles: the submit buttons show their `loading` state and a new submission is ignored. The controls stay enabled. A rejected promise ends the submission and is not caught.

<Preview
    stack
    code={`<oui-form data-demo="async">
    <form class="flex flex-col gap-4">
        <oui-form-field name="email" label="Email" required>
            <oui-input type="email" value="you@example.com"></oui-input>
        </oui-form-field>
        <oui-form-field name="password" label="Password" hint="At least 8 characters." required>
            <oui-input type="password" value="12345678"></oui-input>
        </oui-form-field>
        <oui-button type="submit">Create account</oui-button>
        <p data-result class="text-muted-foreground text-sm"></p>
    </form>
</oui-form>`}
/>

```js
form.addEventListener("oui-submit", (event) => {
    event.detail.waitUntil(save(event.detail.data));
});
```

### Server errors

`setErrors()` displays errors coming from elsewhere, such as a server response. `clear()` removes them. Both take an optional name, or list of names, to act on these fields only.

<Preview
    stack
    code={`<oui-form data-demo="server">
    <form class="flex flex-col gap-4">
        <oui-form-field name="email" label="Email">
            <oui-input type="email" value="you@example.com"></oui-input>
        </oui-form-field>
        <oui-button type="submit">Register</oui-button>
        <p data-result class="text-muted-foreground text-sm"></p>
    </form>
</oui-form>`}
/>

```js
form.addEventListener("oui-submit", (event) => {
    event.detail.waitUntil(
        register(event.detail.data).catch((error) => {
            form.setErrors([{ name: "email", message: error.message }]);
        }),
    );
});
```

### Disabled

`disabled` disables all the controls and prevents submission. Controls that were already disabled stay so when it is removed.

## Usage

After a failed submission, `oui-error` fires and the focus moves to the first field in error. An error that matches no `oui-form-field`, such as a global error of the schema, is only available in `errors` and in `event.detail.errors`.

Only controls inside an `oui-form-field` are validated while the user types and display an error. The others are part of `state` and of the validation on submit.

`validate()` returns the errors instead of throwing them. Each validation of a field runs the whole schema and `validator`, so a `validator` calling a server runs on each trigger.

## API

### oui-form

#### Properties

| Property               | Attribute                 | Type                         | Default                       | Description                                                                                                                                                                                                            |
| ---------------------- | ------------------------- | ---------------------------- | ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `schema`               | —                         | `OuiFormSchema`              | —                             | Standard Schema (Valibot, Zod…) checking the state. Set as a JS property                                                                                                                                               |
| `validator`            | —                         | `OuiFormValidator`           | —                             | Custom validation, combined with `schema`. Set as a JS property                                                                                                                                                        |
| `validateOn`           | `validate-on`             | `OuiFormValidateOn[]`        | `["blur", "change", "input"]` | Events of a field that validate it, as a space-separated list in the attribute. Validation on `input` waits for the first blur of the field, unless it has `eager-validation` or an error. Submitting always validates |
| `validateOnInputDelay` | `validate-on-input-delay` | `number`                     | `300`                         | Delay in milliseconds before validating on `input`                                                                                                                                                                     |
| `disabled`             | `disabled`                | `boolean`                    | `false`                       | Disables all the controls of the form                                                                                                                                                                                  |
| `submitting`           | `submitting`              | `boolean`                    | `false`                       | Whether a submission is running, from its validation to the end of its `waitUntil` promises (read-only)                                                                                                                |
| `dirty`                | `dirty`                   | `boolean`                    | `false`                       | Whether the user changed a control since the last reset or assignment of `state` (read-only)                                                                                                                           |
| `state`                | `state`                   | `OuiFormState`               | —                             | Values of the named controls, typed and nested by the dots of their names. The attribute takes the initial values as JSON. The last assigned state is restored on reset                                                |
| `errors`               | —                         | `OuiFormError[]` (read-only) | —                             | Current errors (read-only)                                                                                                                                                                                             |

#### Methods

| Name          | Description                                                                                                                       |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `validate()`  | Checks the state and displays the errors, of the whole form or only of the given name or names. Returns a promise of these errors |
| `setErrors()` | Replaces all the errors, or those of the given name or names                                                                      |
| `clear()`     | Removes all the errors, or those of the given name or names                                                                       |

#### Events

| Name         | Description                                                                                                                                                                                |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `oui-error`  | The state is invalid; `event.detail.errors` lists the errors                                                                                                                               |
| `oui-submit` | The state is valid; `event.detail.data` is the output of the schema, or the state without schema. A promise given to `event.detail.waitUntil()` keeps the form submitting until it settles |

#### Slots

| Name      | Description  |
| --------- | ------------ |
| (default) | The `<form>` |
